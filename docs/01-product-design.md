# SpaceSlimmer 产品设计方案

## 1. 定位与愿景

### 1.1 定位

**本地、可信、可反悔的媒体空间压缩工具。**

不是“清理大师”，不是剪辑 App，不是格式转换器（虽然转换是能力）。主价值是：

> 你拍下的东西还在；它只是变瘦了。

### 1.2 品类

工具类 / 相册效率 / 存储管理（媒体向）。

对标用户心智：文件管理器里的“压缩视频”功能，但专业度接近桌面 HandBrake 的**简化移动版**，交互接近系统相册。

### 1.3 品牌语义

- **Space**：存储空间，也是“留给生活的空间”。
- **Slimmer**：瘦身，不是删除。

中文产品名建议（可 A/B）：

| 候选 | 说明 |
|------|------|
| SpaceSlimmer（主品牌） | 出海与技术向 |
| 空间瘦身 | 直白，搜索匹配“占空间” |
| 相册瘦身 | 更贴近相册场景，略窄（音频弱化） |

V1 对外名称建议：**SpaceSlimmer（空间瘦身）**，副标题「压缩视频、照片、音频，不删回忆」。

### 1.4 产品原则（按优先级）

1. **原片安全高于压缩率。** 失败、取消、空间不足，一律不影响原片。
2. **先给建议，再给控件。** 默认智能预设能用；高级参数可展开，不挡路。
3. **体积必须可预期。** 开始前给出估算区间，结束后给出真实对比。
4. **快，但是可停。** 批量可暂停、可跳过、可后台；过热自动降并行。
5. **本地优先。** 媒体不上传服务器；分析在端侧完成。
6. **诚实。** 已经很瘦的 HEVC/AV1/HEIC 要明确说“再压收益很小”，而不是硬压出一堆无意义任务。

## 2. 问题拆解

### 2.1 用户真实困境（不只是“文件大”）

| 表层问题 | 深层原因 | 产品应对 |
|----------|----------|----------|
| 存储红了 | 4K/60fps/HDR、连拍、截图、聊天导出 | 扫描大文件 + 一键瘦身 |
| 不敢删 | 情感价值、怕某天要用原片 | 原片保险箱 + 宽限期 + 对比预览 |
| 不知道压什么 | 相册没有“按占用排序的行动” | 空间雷达：按可节省量排序 |
| 压完糊了 | 盲目降分辨率或固定超低码率 | 内容感知预设 + 前后对比 |
| 一个个压太慢 | 工具只支持单文件 | 批量队列 + 分类并行 |
| 格式打不开 | 转了 HEVC 但旧设备不能播 | 导出格式与兼容性档位 |
| iPhone 已经很瘦 | HEVC 再压收益有限 | 分辨率档 + 智能跳过 + 音频/照片补齐价值 |

### 2.2 媒体类型差异（产品必须分开讲，不能一套文案打天下）

**视频**

- 占空间的绝对主力（通常 70%+）。
- 用户对“是否流畅、人脸是否糊”极度敏感。
- 同一条视频，H.264→HEVC 往往比“再压一次 HEVC”更值。
- 4K 日常录像在手机上观看收益低，降到 1080p 是最大杠杆。

**照片**

- 单张不大，但数量巨大（几千到几万）。
- JPEG 仍可用 mozjpeg/AVIF 再抠 20%–60%。
- HEIC 已经高效，默认应更保守，或引导转 AVIF（兼容性要提示）。
- PNG 截图、聊天图是隐性大户。

**音频**

- 人群小于视频，但 WAV 录音压缩比极高，口碑案例好做（“200MB 变 8MB，通话还在”）。
- 已经是 128kbps AAC 的歌曲再压会伤听感，需要智能跳过。

### 2.3 平台差异（产品文案与默认策略不能完全相同）

| | Android | iOS |
|--|---------|-----|
| 视频现状 | 大量 H.264、码率虚高 | 默认 HEVC，已经较瘦 |
| 默认策略 | 转 HEVC/保持 1080p | 先降码率/可选降 1080p |
| 相册写入 | MediaStore / SAF，OEM 碎片 | PhotoKit，规则严 |
| 后台 | 前台服务相对完整 | 后台时间短，必须讲清楚 |
| 格式 | 用户更接受 MP4/H.264 兼容档 | 用户更接受 HEIC/HEVC |

## 3. 用户与场景

### 3.1 人物画像

**A. 家庭记录者（核心）**

- 给孩子、旅行、聚会拍大量视频。
- 不懂码率，只懂“能不能看清脸”。
- 需要：一键、对比、原片可恢复、空间数字刺激。

**B. 内容创作者（高价值）**

- 多段素材、导出上传前要控体积。
- 需要：目标体积、分辨率、码率、格式、批量、不损伤过多细节。

**C. 存储焦虑型安卓用户（量大）**

- 128/256GB 机，相册 + 微信 + 相机把空间吃满。
- 需要：扫描、排序、批量、替换原片释放空间。

**D. 音频场景用户（差异化）**

- 会议录音、课程、语音备忘是 WAV。
- 需要：转 AAC/Opus、保留语音可懂度、批量文件夹。

**E. 极客（口碑传播）**

- 要 CRF/码率/编码速度/容器。
- 需要：高级模式，但不能污染默认 UI。

### 3.2 核心场景（必须打穿）

1. **存储告急**：系统提示空间不足 → 打开 App → 看到“可省 12.4 GB” → 一键均衡压缩前 50 个大文件。
2. **旅行回家**：导入 200 条 4K → 选“高清 1080p”批量 → 晚上充电时跑完 → 第二天确认替换。
3. **发网盘/微信**：单条视频选“目标 20MB / 兼容 H.264”导出副本，原片不动。
4. **截图爆炸**：扫描 PNG/JPEG → 转 JPEG/WebP/AVIF → 批量替换。
5. **录音归档**：选中录音文件夹 → 转 AAC 64–96kbps → 原 WAV 进保险箱。

### 3.3 反场景（引导离开或降级承诺）

- 要做电影级调色、多轨道剪辑 → 引导专业剪辑软件。
- 要压 RAW 成片且零损失 → 说明 RAW 应归档到电脑/NAS。
- 要在 iOS 息屏跑 2 小时 4K 转码 → 明确需要插电点亮/前台，不欺骗后台能力。

## 4. 价值主张与差异化

### 4.1 主价值主张

**智能瘦身，而不是盲目压缩。**

- 先分析：编码、分辨率、码率、是否 HDR、是否已经高效。
- 再决策：转码 / 只转封装 / 降分辨率 / 跳过。
- 再执行：硬件加速 + 分类并行。
- 最后交代：省了多少、画质如何、原片在哪。

### 4.2 差异化支柱

1. **三种媒体一张队列**，不是三个残缺工具拼盘。
2. **空间雷达**：按“预计可节省字节”排序，而不是按时间。
3. **原片保险箱**：压缩 ≠ 删除；替换是二次确认。
4. **同一套 Rust 决策引擎**：安卓/iOS 预设行为一致，口碑可复用。
5. **兼容档 vs 高效档**：用户能懂的两句话，而不是 codec 名词考试。
6. **真实预估**：给区间，不给假精确到 KB 的谎言。

### 4.3 竞品策略（产品层面）

市场上常见失败模式：

- 压缩很猛，脸糊，差评。
- 只能单个文件，批量是会员墙且不稳定。
- 广告清理 App 夹带压缩，不专业。
- 桌面级参数堆砌，普通人不会用。

SpaceSlimmer 赢面：**默认像系统功能，高级像 HandBrake，结果可对比，原片可反悔。**

## 5. 功能架构

功能按层次，不按页面堆砌。

### 5.1 必做（P0，V1 必须）

**获取与选择**

- 系统照片选择器（单选/多选）。
- 文件选择器（视频/音频/图片，含下载目录、录音目录）。
- 空间雷达：在用户授权范围内扫描，列出大文件与预计节省。
- 按类型筛选：视频 / 照片 / 音频 / 全部。
- 按预计节省、大小、日期排序。

**压缩能力**

- 视频：分辨率档、质量档、目标体积、输出格式（至少 MP4）。
- 照片：质量档、输出格式（JPEG / WebP / AVIF / 保持原格式）。
- 音频：质量档、输出格式（AAC / Opus / MP3）。
- 批量一键：同一预设应用到整个选择集。
- 智能跳过：预估节省低于阈值则跳过并说明原因。

**任务系统**

- 队列、并行、暂停、继续、取消单项、取消全部。
- 单项进度（0–100% + 当前文件名 + 速度）。
- 失败原因可读（不支持的编码、磁盘满、权限、被系统杀掉）。
- 应用在前台时稳定跑完；Android 支持前台服务通知。

**结果与安全**

- 前后大小对比、节省总量。
- 视频/照片对比预览（滑杆对比；视频支持关键帧/短预览）。
- 导出到相册或指定目录。
- **默认另存为新文件**；“替换原片”需二次确认。
- 原片保险箱（应用管理的原片目录/相册）+ 7 天默认宽限（可设置）。

**设置**

- 默认预设、默认导出位置、是否保留元数据、是否保留 HDR、并行度（自动/省电/最快）。
- 保险箱自动清理提醒。

### 5.2 应做（P1，V1.x）

- 目标体积模式（“压到 50MB 以下”）。
- 仅音频转码、视频音轨降码率。
- Live Photo / Motion Photo 策略（静态图压缩 + 视频轨可选）。
- 文件夹/相册级一键。
- 充电且 Wi-Fi/闲时才跑（本地任务，与网络无关，但是“充电时”）。
- 压缩历史（可复盘、可分享报告）。
- HEVC / AV1 输出在设备支持时开放。
- 自定义：分辨率、帧率上限、视频码率、音频码率、编码器偏好。

### 5.3 可做（P2）

- 片段压缩（裁时间再压，仍不做完整剪辑）。
- 批量重命名、按日期归档导出。
- 桌面版同源引擎（非 V1）。
- 观看报告：哪类文件最占空间。
- 小组件：本周已省空间。
- Siri / App Intents / Android Shortcut：“压缩最近一周视频”。

### 5.4 明确不做

- 云端上传压缩。
- 自动静默删除原片。
- 破解/去除水印类能力。
- 伪装成杀毒/内存加速。
- 社交动态。

## 6. 信息架构

```
启动
 ├─ 首页（空间雷达 + 快捷操作）
 ├─ 选择页（系统 Picker / 雷达列表多选）
 ├─ 预设与参数页（智能默认 + 高级折叠）
 ├─ 任务中心（进行中 / 排队 / 完成 / 失败）
 ├─ 结果页（对比、替换、分享、保存）
 ├─ 保险箱（原片、到期提醒、恢复）
 ├─ 历史
 └─ 设置 / 会员
```

### 6.1 首页

首屏三块，避免做成功能宫格。

1. **空间摘要卡**
   - 已分析范围（全部相册 / 仅选定项）。
   - 媒体占用估算。
   - **预计可节省**（大字）。
   - CTA：一键智能瘦身。
2. **快捷入口**：选视频 / 选照片 / 选音频 / 从文件选。
3. **大文件清单**（Top N）：缩略图、时长/尺寸、当前体积、预计节省、复选。

空状态：未授权时讲清“我们只在本地分析，不会上传照片”，给最小权限路径（系统 Picker）和完整雷达路径（相册权限）。

### 6.2 预设页（产品关键页）

结构固定为四段，防止参数爆炸：

1. **目的选择**（互斥大卡片）
   - 尽量画质（适合以后还要剪辑/大屏）
   - 均衡推荐（默认）
   - 尽量瘦身（适合存档/微信）
   - 指定体积
   - 自定义
2. **清晰度/分辨率**（视频）或 **输出规格**（图/音频）
3. **导出格式 + 兼容性**
   - 高效（HEVC/AVIF/Opus，更瘦）
   - 兼容（H.264/JPEG/AAC，更好开）
4. **输出策略**
   - 另存新文件（默认）
   - 压完后询问是否替换
   - 替换并送入保险箱

底部固定：**预计输出体积区间**、**预计耗时档**（很快/数分钟/建议插电）、开始按钮。

### 6.3 任务中心

- 整体进度：完成数 / 总数，已省空间（实时累加）。
- 每个条目：缩略图、状态、进度条、可跳过。
- 全局：暂停、取消、省电模式（降并行）。
- 锁频/切到后台：Android 通知栏进度；iOS 横幅说明“请保持应用打开以继续转码”。

### 6.4 结果与对比

- 总节省、成功率、跳过原因聚合（“12 个已经很瘦，已跳过”）。
- 单项：原 842MB → 新 276MB，-67%。
- 对比：照片前后滑杆；视频播放器支持左右或滑杆（实现见技术方案，V1 可用前后切换 + 放大）。
- 主按钮：保存到相册 / 完成。
- 危险按钮：替换原片（二次弹窗，写清楚保险箱保留天数）。

### 6.5 保险箱

- 列表：原片、对应瘦身文件、到期日。
- 操作：恢复原片、立即删除原片、延期。
- 到期通知：本地通知，默认不自动删，改为“到期提醒 + 一键清空到期项”（设置里可改为到期自动删，默认关）。

## 7. 关键用户流程

### 7.1 主路径：雷达一键瘦身

1. 授权（Picker 或相册）。
2. 首页展示可省空间。
3. 用户点「智能瘦身」，进入已勾选 Top 文件的确认页。
4. 默认「均衡 + 高效或兼容（按平台默认）」 。
5. 显示预估：文件数、预计耗时、预计节省 8.6–11.2 GB。
6. 开始；任务中心跑。
7. 完成；对比；默认另存。
8. 若用户选替换：原片进保险箱。

### 7.2 单文件精确控制

1. 从相册选一条 4K。
2. 预设改「指定体积 64MB」。
3. 选择兼容 MP4 H.264（要发微信）。
4. 预览估算约 60–70MB，若达不到则提示需降到 720p。
5. 导出副本，原片不动。

### 7.3 批量照片

1. 选一个相册或多选 200 张。
2. 输出 JPEG 质量「高」或 AVIF「均衡」。
3. 并行压缩，任务列表滚动。
4. 跳过已经很小的图（如 < 200KB 且非 PNG）。

### 7.4 失败与中断

- 磁盘不足：停止后续任务，已完成保留，未开始不碰。
- 应用被杀：Android 前台服务尽量保活；重启后可恢复未完成队列。
- 用户取消：删除不完整临时文件，原片不动。

### 7.5 首次启动

1. 三屏以内：痛点（空间）→ 原则（本地、可反悔）→ 权限。
2. 提供两条路径：**先选几个文件试试**（低权限）/ **扫描相册找出肥文件**（高权限）。
3. 第一次压缩强制走「另存」，让用户建立安全感后再暴露替换。

## 8. 压缩预设（产品定义，算法映射见 03）

命名面向人，不面向工程师。内部 ID 稳定，UI 文案可本地化。

### 8.1 视频质量档

| ID | 用户名称 | 用户能理解的效果 | 典型策略意图 |
|----|----------|------------------|--------------|
| `v_visually_lossless` | 极致画质 | 几乎看不出差别，体积小降 | 同分辨率，温和降码，优先更高效编码 |
| `v_high` | 高清 | 大屏也清晰 | 最高 1080p 或保持（若源更低），高质量 |
| `v_balanced` | 均衡（默认） | 手机上看很清晰，体积明显变小 | 最高 1080p，中高码率，高效编码 |
| `v_small` | 小体积 | 微信/网盘友好 | 最高 720p，中码率 |
| `v_tiny` | 极简 | 只为留下内容 | 最高 540p，低码率 |
| `v_target_size` | 指定体积 | 我说了算 | 反推码率，必要时自动降分辨率 |
| `v_custom` | 自定义 | 全参数 | 用户锁分辨率/帧率/码率/编码 |

**默认：Android `v_balanced` + 高效 HEVC（不支持则 H.264）；iOS `v_balanced` + HEVC。**

### 8.2 视频清晰度档（可与质量档组合，也可由质量档锁定）

- 保持原分辨率
- 4K
- 1080p
- 720p
- 540p
- 自动（由质量档决定）

规则：输出分辨率永不高于源（除非未来做超分，V1 不做超分）。

### 8.3 视频导出格式

| 用户选项 | 容器 | 视频编码 | 音频 | 何时建议 |
|----------|------|----------|------|----------|
| 兼容 | MP4 | H.264 | AAC | 分享、旧设备、微信 |
| 高效 | MP4 | HEVC | AAC | 本地存档（默认高效） |
| 更高效 | MP4 | AV1（设备支持时） | AAC/Opus | 旗舰机、不急 |
| 原格式 | 尽量保持 | 仅改码率/分辨率 | 按需 | 进阶 |

V1 必须：兼容 MP4/H.264、高效 MP4/HEVC（硬件可用时）。AV1 为 P1。

### 8.4 照片

| ID | 名称 | 意图 |
|----|------|------|
| `i_max` | 最高画质 | 肉眼无损，温和再压缩 |
| `i_high` | 高清（默认） | 社交/相册够用 |
| `i_small` | 小体积 | 明显瘦身 |
| `i_format` | 指定格式 | JPEG / WebP / AVIF / PNG / HEIF |

智能：PNG 截图默认可转 JPEG/WebP；带透明通道的 PNG 保持 PNG 或 WebP/AVIF 透明。

### 8.5 音频

| ID | 名称 | 意图 |
|----|------|------|
| `a_speech` | 语音（默认对 WAV 录音） | 64–96kbps AAC/Opus，可懂 |
| `a_music_high` | 音乐高品质 | 192–256kbps AAC |
| `a_music_small` | 音乐小体积 | 96–128kbps |
| `a_keep_lossless` | 不转有损 | 仅 FLAC 再封装或跳过 |

### 8.6 智能跳过（产品文案必须有）

跳过并告诉用户原因，例如：

- 「已经是高效编码，再压只能再省 3%，已跳过」
- 「文件小于 2MB，收益太小」
- 「预估会压更大，已跳过」
- 「HDR 电影模式暂不支持，已跳过」（直到能力就绪）

跳过阈值产品默认：

- 预计节省 < 8% **且** < 5MB：跳过（视频）。
- 预计节省 < 10% **且** < 200KB：跳过（照片）。
- 源音频已 ≤ 目标码率的 1.1 倍：跳过。

用户可在设置关闭智能跳过。

## 9. 批量、并行与“快”的产品表达

用户要的“多线程快”，产品上要翻译成可感知行为：

- 照片/音频：同时压多张，进度列表多个 `进行中`。
- 视频：默认同时 1 条（防发热）；旗舰机「最快」可 2 条；设置里写清「视频双开会更烫、可能更慢」。
- 混合队列：视频 1 路 + 照片 N 路同时跑（照片不抢满 CPU 时）。
- 热了：自动降到 1 路，SnackBar「设备发热，已降低并行」。
- 电量 < 15% 且未充电：询问是否继续。
- 给出速度感：MB/s、剩余时间、已省空间跳动。

**不要承诺“永远实时”。** 4K HEVC 软件编码会慢。产品按档显示耗时：

- 很快：照片、音频、720p 硬件
- 中等：1080p 硬件
- 建议插电：4K、AV1 软件、超大批量

## 10. 格式与能力矩阵（产品承诺）

### 10.1 输入（V1 以“能压”为承诺，不能压要明确失败）

**视频输入：** MP4、MOV、M4V、3GP；尽力：MKV、WEBM（P1）。  
常见编码：H.264、HEVC、VP9；尽力：AV1、MPEG-4。

**照片输入：** JPEG、PNG、WEBP、HEIC/HEIF、GIF（V1 仅静态或首帧策略需定：GIF 动画 P1 保持/转 MP4）。  
BMP、TIFF：P1。RAW：V1 只读预览不压缩，提示用电脑。

**音频输入：** M4A、AAC、MP3、WAV、FLAC、OGG；AMR：P1。

### 10.2 输出（V1）

- 视频：MP4（H.264 / HEVC）
- 照片：JPEG、WebP、AVIF（AVIF 若包体积过大可 P1，但方案按支持设计）
- 音频：M4A/AAC、Opus（OGG/WEBM）、MP3（若专利/库体积不允许，MP3 可 P1）

### 10.3 元数据

默认保留：拍摄时间、方向、位置（位置单独开关，默认跟随系统隐私：iOS 可剥离 GPS）。  
可剥离：GPS、设备型号、人脸区域（P2）。  
视频旋转：优先保留 rotation 矩阵，避免画质二次损伤。

### 10.4 特殊媒体

| 类型 | V1 策略 |
|------|---------|
| Live Photo | 压静止图；视频轨可选压或保留 |
| Motion Photo | 拆出静态 JPEG 压；嵌入视频 P1 |
| HDR / Dolby Vision | 能硬件透传则保留；否则跳过或转 SDR 并强提示 |
| 慢动作 / 电影效果 | 先跳过，避免破坏时间元数据 |
| 连拍 | 当普通照片批量 |
| 截图 PNG | 默认可转 JPEG/WebP |

## 11. 交互与视觉设计方向

### 11.1 气质

干净、系统化、数字可信。参考：系统文件 App + 健康 App 的摘要卡，而不是清理软件的红色恐吓。

- 主色：空间蓝/石板色，节省数字用正向绿色。
- 危险操作（删除原片）才用红。
- 大量用图表：前后体积条、环形可省比例。

### 11.2 文案语气

- 不说“粉碎、永久清除、加速手机”。
- 说“瘦身、另存、原片在保险箱”。
- 参数用「清晰度」而不是只抛 CRF。

### 11.3 无障碍与国际化

- 动态字体、对比度、VoiceOver/TalkBack（进度百分比要可读）。
- 先中英；单位用 MB/GB，尊重系统 1000/1024 显示习惯（统一 GiB 需在设置说明）。建议显示采用 **1000 进制（系统常见）**，内部计算用字节。

### 11.4 平台惯例

- Android：Material 3，预测性返回，通知渠道「压缩任务」。
- iOS：SwiftUI NavigationSplit/Stack，相册权限 Limited Library 横幅，能量模式提示。

## 12. 权限与信任

权限是转化杀手，采用**阶梯授权**：

1. 零相册权限：系统 Picker 选中的文件也能压（Android Photo Picker / iOS PHPicker）。
2. 雷达需要更广读取：Android 分媒体权限；iOS 完整相册或有限相册。
3. 写入相册：另给保存权限/添加权限。
4. 通知：仅任务开始时再要。

信任文案固定出现在授权前：

- 媒体只在本机处理。
- 无账户也可完整使用核心压缩（登录仅用于会员同步，V1 甚至可无账户 IAP）。

## 13. 商业化（建议，可随地区改）

工具 App 要避免“压完加广告水印”这种毁口碑模式。

### 13.1 推荐模型：免费好用 + 订阅/买断解锁效率

**免费永远保留**

- 单次最多 N 个文件（建议视频 3、照片 20、音频 10）。
- 均衡/高清/小体积预设。
- 兼容格式导出。
- 对比预览、另存。

**Pro**

- 无限批量。
- 指定体积、自定义参数。
- HEVC/AV1 高效档、AVIF。
- 保险箱自动策略、历史导出。
- 并行「最快」档。
- 去除将来可能的导出品牌帧（若有；建议永远不要水印）。

价格建议：年订为主，买断为辅（地区合规注意）。不在压缩进度中插广告。

### 13.2 增长

- 完成页「已省 3.2 GB」分享卡片（不分享用户照片，只分享数字）。
- 存储满时的系统场景：需靠 ASO（关键词：压缩视频、减小视频、相册空间、compress video）。

## 14. 指标

### 14.1 产品北星

**每周成功释放的字节数（用户确认保存/替换后的净节省）。**

### 14.2 体验指标

- 授权完成率（Picker 路径 vs 雷达路径）。
- 首次压缩完成率。
- 跳过率与跳过原因分布（过高说明预估或默认档有问题）。
- 失败率（按错误码）。
- 替换原片率 vs 另存率（过低说明不信任，过高要防误删）。
- 保险箱恢复率（高说明误伤画质）。
- 平均节省比（分视频/图/音频，分 iOS/Android）。
- 任务中位耗时、过热降级次数。
- 评分与“糊/卡/失败”差评主题。

### 14.3 质量指标（抽检，实验室）

- 标准样片集的体积比、卡顿（掉帧感知）、人脸区域主观分。
- 不在客户端默认跑 VMAF（太重）；实验室可跑。

## 15. 合规、隐私、法律（产品侧）

- 隐私政策：本地处理、崩溃日志不含媒体内容、分析事件只含文件类型/大小档位/耗时，不含路径和缩略图上传。
- 相册访问目的说明字符串写具体。
- 导出 HEVC/AAC 依赖系统编码器，降低专利风险（见技术文档）。
- 未成年人：无 UGC 社交则风险低；仍需隐私清单。
- 用户可删除保险箱与历史。

## 17. V1 范围冻结（给研发的合同）

V1 可以发布的最小完整产品：

1. 选文件（Picker）+ 可选雷达扫描（授权后）。
2. 视频/照片/音频都能压，批量队列。
3. 三档常用质量 + 兼容/高效格式。
4. 预估体积区间、智能跳过、失败不影响原片。
5. 任务暂停取消、Android 前台服务。
6. 另存默认、可选替换+保险箱（至少 7 天手动清理）。
7. 结果对比（照片滑杆，视频前后切换）。
8. 本地化中英。

卡住发布的缺口：无批量、无预估、替换直接删原片、只能压一种媒体、iOS/Android 行为完全不一致。
